## Critical integrity finding

The user's original *raw material* archive is still not present in the located source files. The migrated objects therefore use `FINAL_PUBLICATION_MIGRATION` provenance and are not represented as the original raw input.

This is intentional. The application must never claim that a polished final brief is the raw source.

## Publication status

Both weeks remain `MIGRATED_REVIEW`, not `PUBLISHED`.

Before changing to `PUBLISHED`:
1. Attach the original raw Week 31 and Week 32 input archive separately.
2. Verify the migration against the raw material.
3. Preserve the pre-outcome snapshot.
4. Run content validation.
5. Run desktop + phone QA.
6. Only then promote the week.

## Architectural result

The real Week 31 and Week 32 content now exercises the same content contract used by the Brief, 5D and Simulator. This is the first meaningful stress test of the permanent architecture.
